## サービス名 : TORUNTO - 撮らんと？ -

## サービス概要

## このサービスへの思い・作りたい理由
「視る」から「学ぶ」へ。<br>
instagramやXなど、SNSには日々たくさんの素敵な写真が投稿されています。<br>
「この写真、すごく綺麗だな」<br>
「こんな写真を自分も撮ってみたい」<br>
そう思った経験がある人は多いのではないでしょうか。<br>
しかし、写真を「視る」だけで終わってしまい、実際にカメラを持って撮影してみるところまで踏み出せない人もいると思います。<br>
自分自身、写真を撮ることが好きで、写真には「同じ場所・同じ被写体でも、撮り方によって全く違った表現ができる」という魅力があると感じています。<br>
だからこそ、素敵な写真をただ視るだけではなく、「なぜこの写真は魅力的なのか」「どんな設定や構図で撮影しているのか」を知り、写真を撮るための知識を学べる場所を作りたいと考えました。<br>
そこで生まれたのがTORUNTO - 撮らんと？ - です。<br>
「撮らんと？」は私の地元である福岡の方言で、「撮らないの？」や、「撮りに行こうよ」という意味です。<br>
そして、英語のRUN toには「～へ向かう」という意味があります。<br>
写真を視るだけで終わらず、写真から撮影方法を学び、そして実際にカメラを持って撮影へ向かう。<br>
「視る」から「学ぶ」へ。<br>
「学ぶ」から「撮る」へ。<br>
TORUNTOを通して、写真をもっと身近に感じてもらい、「自分も撮ってみよう」と一歩踏み出すきっかけを作りたいと思っています。<br>

## ユーザー層

- カメラに興味があるけれど、何から始めたらいいかわからない人（初心者層）<br>
  どうすれば思い通りの写真が撮れるかわからない人<br>
  実際に撮影された写真を見ながら、撮影時のカメラ設定や撮影技法、構図などを学ぶことができます。<br>
  また、「この写真を撮ってみたい」という興味をきっかけに、具体的な撮影方法を知ることができるため、<br>
  カメラ初心者でも「視る」だけで終わらず、「学んで撮ってみる」ためのきっかけを得ることできると考えています。<br>

- さらに新しい撮影技法を身に着けたい人（中堅者層）<br>
  基本的な撮影方法を身に付けた後、さらに写真表現の幅を広げるための知識や技法を学ぶことができます。<br>
  「知っているけれど、実際にどうやるのかわからない」という技法について、他のユーザーの写真や撮影方法を参考にしながら、<br>
  新しい撮影方法や機材、表現方法に挑戦するきっかけを得ることができると考えております。<br>

- 自分の経験や撮影技法を他のユーザーに教えたい人、カメラや写真の魅力をより多くの人に広めたい人（上級者層）<br>
  自分が持っている撮影技術や知識、撮影スポットなどを他のユーザーに共有することで、<br>
  写真を学びたい人と知識を持っている人をつなぐことができます。<br>
  また、自分の知識や経験を発信することで、他のユーザーから新たな知識や撮影方法を得ることにもつながります。<br>

## サービスの差別化ポイント・推しポイント
　【似たようなサービス】
- 「GANREF ([参考URL](https://ganref.jp/))」:<br>
  初心者が写真を撮るとは何か、何から学んでいけばいいのか分かる点が差別化点と考えています。<br>
  GANREFさんは機能が非常に多く、総合的な写真コミュニティに位置付けられている印象を持ちます。<br>
  しかし、写真の知識がある程度ないとどうやって撮影したのか、撮影技法がわからない初心者には、<br>
  触れやすいコミュニティではないと感じました。<br>
  本サービスでは、初心者が理解できるように撮影技法や用語をまとめ、写真を撮るためのスタート台を用意します。<br>

- 「500px ([参考URL](https://500px.com/))」:<br>
  上級者だけでなく初心者も学べる点が差別化点と考えています。<br>
  500pxさんは作品の鑑賞・共有や写真家としての活動に長けていると感じました。<br>
  本サービスでは、上級者だけの世界にせず、カメラを買ったばかりの人でも参加できる写真コミュニティにできます。<br>
  
- 「PHOTOHITO ([参考URL](https://photohito.com/))」:<br>
  撮影情報を表示するだけではなく、その情報を学習につなげる点が差別化点だと考えています。<br>
  PHOTOHITOさんはカメラ・レンズ・シャッタースピードなど撮影情報が記載されており、<br>
  どのような設定で撮ったのか調べられるという意味では、本アプリと近いです。<br>
  本サービスでは、単に撮影情報を確認するだけでなく、なぜその設定で撮影したのか、<br>
  撮影時に何を意識したのかなど、写真が生まれた過程を知ることができるサービスを目指します。<br>
  ※PHOTOHITOさんは2026年9月30日をもってサービス終了予定と発表されています。<br>

本サービスの推しポイントは、
-  『 写真を見るだけでなく、撮影設定や構図・技法を知り、どう撮ったのかを学べる 』
-  『 F値などの専門用語をクリックするだけで特徴を確認でき、初心者でも迷わず知りたい情報に辿り着ける』
-  『 写真を見る→学ぶ→実際に撮影するという導線を作り、写真を始めるきっかけを提供する』
<br>

と考えています。写真やカメラに興味はあるけれど、何から学んでいけばいいのかを解決するものです。<br>
複雑な機能・UIは付けず、初心者から上級者まで使いやすいサービスを目指しています。<br>

## このサービスで提供したい価値
- ユーザーの変化<br>
  このサービスを使うことで、ユーザーに以下のような変化を提供します。<br>
  ・行動の変化：写真を見るだけで限らず、撮影方法を学び、実際にカメラを持って撮影するようになる。<br>
  ・気持ちの変化：「カメラは難しそう」という気持ちから、「自分もこんな写真を撮ってみたい」という前向きな気持ちになる。<br>
  ・考え方の変化：写真をただ鑑賞するだけでなく「この写真はなぜ綺麗に見えるのか」「どのような設定・構図・技法が使われているのか」<br>
  と、写真を分析して見るようになる。<br>

- 価値を一文で表す<br>
  「写真を見るだけで終わらず、撮影方法を学び、自分でも写真を撮ってみたくなるサービス」<br>
  TORUNTOのコンセプトである、「視る」から「学ぶ」へ。<br>
  を、実現し、最終的に「学ぶ」から「撮る」へつなぎます。<br>

## このアプリの懸念点とその対策
- 懸念点①
  写真SNSとして既存サービスとの差別化が難しい。<br>
  何が問題になりそうか：<br>
  写真投稿・共有・検索などの機能は、既存の写真サービスにも存在するため、単純な写真SNSとしてはTORUNTO独自の価値を出しにくい。<br>

  なぜそう思うのか：<br>
  GANREFやPHOTOHITOなど、写真の投稿・閲覧や、撮影情報の確認ができるサービスがすでに存在しているため。<br>

  そのために考えている対策：
  写真を投稿するだけでなく、「写真から撮影方法を学ぶ」ことをサービスの中心にする。<br>
  例えば、写真に表示された「F値」を押すことで、<br>
   ・ F値とは？<br>
   ・ F値を小さくするとどうなる？<br>
   ・ この写真ではなぜこのF値を使っている？<br>
　といった情報を確認できるようにし、単なる撮影情報ではなく学習につなげる情報として提供する。<br>

- 懸念点②
  情報量が多くなり、初心者には分かりくくなる可能性がある。<br>

  何が問題になりそうか：<br>
  カメラにはF値、ISO感度、シャッタースピード、焦点距離など多くの専門用語があり、情報を詰め込みすぎると初心者が使いにくくなる。<br>

  なぜそう思うのか：<br>
  「初心者でも写真を見ながら学べる」というTORUNTOの目的と、情報量の多さが矛盾する可能性があるため。<br>
  
  そのために考えている対策：<br>
  シンプルなUIと分かりやすい導線を意識する。<br>
  例えば、「F2.8」という項目をクリックすると、<br>

    F値とは？<br>
    レンズの絞り具合を表す数値。<br>
    数値が小さいほど背景をぼかしやすくなります。<br>

  というように、その場で簡単に理解できる設計にする。<br>
  「知りたい情報を押すだけで分かる」UIにすることで、初心者でも迷わず利用できるようにする。<br>

## 今後の展開・発展の方向性
- 観点<br>
  ユーザーはなぜ使い続ける？<br>
  自分が撮りたい写真の撮影方法を調べたり、他のユーザーの写真から新しい技法を学んだりできるため。<br>
  また、自分の写真を投稿することで、他のユーザーに知識や撮影方法を共有することもできる。<br>
  続けることで何が変わる？<br>
  写真を見るだけだったユーザーが、撮影技法やカメラの知識を身に着け、実際に撮影するようになる。<br>
  さらに、撮影経験が増えることで、より高度な撮影技法やRAW現像、フィルムカメラなど、<br>
  新しい写真表現にも挑戦できるようになる。<br>
  データが溜まると何ができる？<br>
  写真・撮影設定・撮影技法・撮影場所などのデータが蓄積されることで、<br>
  - 撮影技法から写真を探す
  - 撮影スポットから写真を探す
  - 「玉ボケを使った写真」など、撮りたい表現から探す
  - 自分が学んだ撮影技法を管理する
  <br>

  といった機能への発展が考えられる。<br>

  他の人と関わる余地がある？<br>
  上級者が撮影技法や撮影スポットを共有し、初心者・中堅者がそこから学ぶことで、ユーザー同士の知識共有につなげる。<br>

- 今考えている発展案<br>
  機能追加の方向性：<br>
   - 撮影スポット検索
   - 撮影技法・構図の解説
   - カメラ・レンズ情報
   - RAW現像やフィルムカメラなど、より専門的な情報の追加
  <br>
  UI・体験の改善：<br>
   - 初心者でも直感的に操作できるシンプルなUI
   - 情報を必要以上に表示せず、クリックすることで詳細を確認できる設計
   - 「視る→学ぶ→撮る」の導線をより分かりやすくする
  <br>
  機能以外の工夫：<br>
   - ユーザー同士が撮影方法を教え合える環境を作る
   - 初心者から上級者まで、それぞれのレベルに合った学びを提供する
  <br>

  ## 技術スタック
  - 使用予定の技術<br>

  | カテゴリ | 技術構成 |
  | ---- | :--- |
  | フロントエンド | HTML / CSS / JavaScript / Hotwire（Turbo・Stimulus）|
  | バックエンド | Ruby 3.3.5 / Ruby on Rails 7.2 |
  | データベース | PostgreSQL |
  | 画像管理 | Acitve Storage |
  | 認証 | Devise |
  | 開発環境 | WSL / Docker |
  | テスト | Rspec |
  | バージョン管理 | Git / Github |
  | CI/CD | GitHub Actions |
  | デプロイ | Render |

  【選定理由】
  メインの技術であるRails、Ruby、データベース、デプロイサーバーを選定した理由を簡単に述べます。
  - Ruby / Ruby on Rails ：
    Ruby on Railsを採用しました。<br>
    ユーザー登録、写真投稿、コメント、いいね、撮影情報の管理など、データベースと連携したWebアプリケーションを効率的に開発できるためです。
    また、現在学習しているRuby on Railsの知識を活かしながら、MVC構造やRESTfulな設計について理解を深めることも目的としています。

  - データベース ：
    PostgreSQLを採用しました。<br>
    ユーザー情報や写真、撮影設定、撮影技法、コメントなど、TORUNTOでは多くのデータを関連付けて管理する必要があります。
    PostgreSQLはリレーショナルデータベースとして複雑なデータの関連付けに適しており、MySQLと比較しより複雑なデータの扱いに強いPostgreSQL採用しました。
  
  - デプロイサーバー ：
    Renderを採用しました。<br>
    同水準のサーバー候補として、Herokuと比較検討しましたが、今回のサービス規模においてコスト面でRenderが適していると考えました。
    加えて、RailsアプリケーションやPostgreSQLとの連携を比較的容易に構築でき、個人開発でのデプロイ先として扱いやすいため採用します。
